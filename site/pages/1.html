Each idle worker splits the largest remaining range in half and takes the tail.

Written straight into one preallocated file at each range's own offset. No part files, no merge step.

Dynamic segmentation, not fixed chunks

Splitting a file into eight equal pieces up front means seven fast connections idle while one straggler finishes. DM decides the split as it goes.

  1. Start with the whole file as one range

    The first worker begins at byte zero. Nothing is planned in advance.

  2. Idle workers split the largest remaining range

    Each takes the tail half of whatever has the most left. The same code path handles the initial fan-out and late rebalancing.

  3. Slow connections end up owning less

    A throttled socket gets its range split away from it, so the transfer ends when the fast ones finish, not when the slow one does.

  4. Bytes land at their offset, once

    Every range writes into the same preallocated file with a positioned write. The download is complete the moment the last range is.

Browser hand-off

The Chrome extension catches downloads and passes them over with the session's cookies, so logged-in files just work.

Resume after anything

Ranges are recorded as they land. Restart the app, the PC, or the network and the download continues from where it stopped.

Streaming video to MP4

HLS playlists are fetched segment by segment and, when ffmpeg is present, stitched into a single MP4.

Native Windows app

Dark by default. Tray icon, save-as and progress dialogs, a finished dialog, and a web UI at localhost when you prefer a browser tab.

When it finishes

Open the file, open the folder, or let the PC sleep, shut down or restart once the queue empties.

Light on the machine

Written in Go with no third-party modules. The idle daemon sits around 9 MB of memory.

One setup file, no admin prompt

DM-Setup.exe installs the app, registers the browser hook and offers the extension. The same file uninstalls, and leaves your download list alone unless you say otherwise.
