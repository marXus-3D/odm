An 83 MiB file from dl.google.com. One connection, the browser's way, against eight. Same machine, same bytes.

I.

Hosts cap the socket, not the person.

Most servers throttle each connection. A busy link, likewise, is shared per flow rather than per user. Eight connections therefore claim eight shares and each ramps up on its own.

DM splits the remaining bytes as it goes: an idle connection halves the largest remaining range and takes the tail, so a slow socket never sets the finishing time. Every byte is written to its final offset. There are no part files and no merge.

II.

Nothing is lost to an interruption.

Finished ranges are recorded as they land. Close the app, restart the machine, lose the network; the transfer continues from the byte it stopped at.

Streaming video is treated the same way. Playlists are fetched segment by segment and, with ffmpeg present, written out as a single MP4.

III.

Four ways in, one list underneath.

A dark native window with a tray icon, save-as and progress dialogs, and finish actions. A web page on localhost that shows the same list. A command line for scripts.

And an extension for Chrome, Edge, Brave and Vivaldi that intercepts downloads and hands link and cookies to DM over native messaging, so files behind a login download the way they would in the browser, only faster.

Written in Go, without dependencies.
